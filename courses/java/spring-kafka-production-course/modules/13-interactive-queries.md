## 1. Academic Lecture: Queryable Stores, Metadata Routing & Distributed Queries

### Basic Level: Introduction to Interactive Queries

#### What are Interactive Queries (IQ)?
Normally, to view data generated by Kafka Streams, you must output the results to an external database (e.g. Elasticsearch, MySQL) and query that database.
* **Interactive Queries**: Allow your Spring Boot application to query the local state stores (RocksDB) directly via REST APIs, bypassing external databases. This saves storage overhead, eliminates write latency, and makes your application a distributed database.

```text
  [ Client REST Request ] ──► [ Spring Controller ] ──► [ RocksDB State Store ]
```

#### Querying Key-Value Stores
To query a store:
1. Fetch a reference to the store using `StreamsBuilderFactoryBean.getKafkaStreams()`.
2. Retrieve the store using `StoreQueryParameters.fromNameAndType()`.
3. Call store lookup methods:
   * Point lookup: `store.get("customerId-123")`.
   * Range scan: `store.range("customer-001", "customer-100")`.

---

### Intermediate Level: State Discovery & KeyQueryMetadata

#### The Distributed State Store Challenge
Since Kafka topics are partitioned, Kafka Streams distributes tasks across multiple microservice instances (e.g., 3 running pods).
* **Local State Partitioning**: Pod A only contains state for partitions 0-2. Pod B contains state for partitions 3-5.
* **The Problem**: If a client calls Pod A querying the balance of key `customer-888`, but key `customer-888` belongs to partition 4 (which lives on Pod B), Pod A cannot find the record in its local RocksDB store.

#### Metadata Discovery API
Kafka Streams provides metadata lookup APIs to locate keys:
* **`StreamsMetadata`**: Contains information about active instances (host IP and port) and the partitions assigned to them.
* **`KeyQueryMetadata`**: Resolves which specific host instance currently owns the queried key.
  * *Method*: `kafkaStreams.queryMetadataForKey("customer-spend-store", key, Serdes.String().serializer())`.

---

### Advanced Level: Metadata Routing & Forwarding

To support queries across the entire distributed cluster, we implement a **Metadata Routing Pattern**:

```text
               [ Client Query for "key-999" ]
                             │
                             ▼
                    [ App Pod A (Port 8080) ]
                             │
            (Check: Where is key-999 partition?)
                             │
                             ├─────── (Local? Yes) ──► Query local RocksDB
                             │
                             └─────── (Remote? Pod B) ──► REST Forward (WebClient) ──► [ Pod B ] ──► Query local RocksDB
```

1. The client queries Pod A.
2. Pod A calls `queryMetadataForKey` for the target key.
3. If the metadata points to Pod A itself, it queries its local RocksDB store and returns the result.
4. If the metadata points to Pod B (port 8081), Pod A calls a REST endpoint on Pod B using Spring's `WebClient`.
5. Pod B queries its local RocksDB store, returns the payload to Pod A, which returns it to the client.

## 2. Theory & Production Best Practices

### Interactive Queries vs. External Databases

| Feature | Interactive Queries (RocksDB) | Traditional External Database |
| :--- | :--- | :--- |
| **Write Latency** | None (direct stream write) | High (requires database inserts/commits) |
| **Infrastructure Overhead** | None (embedded C++ database) | High (requires hosting DB cluster) |
| **Network Hops** | 1-2 hops (direct or forward) | Multi-hops (write to DB, query from API) |
| **Complex Joins Support** | Hard (must structure key indexes) | Easy (supports SQL joins and schemas) |

### Point Lookups vs. Range Scans

| Lookup Type | Store Method | Performance | Best Use Case |
| :--- | :--- | :--- | :--- |
| **Point Lookup** | `store.get(key)` | O(1) time complexity | Fetching account balance, profile lookups. |
| **Range Scan** | `store.range(from, to)` | O(N) scan duration | Fetching list items, alphabetized listings. |

## 3. Common Errors & Troubleshooting

### 1. InvalidStateStoreException: State Store is closed
* **Symptom**: REST lookup fails with `org.apache.kafka.streams.errors.InvalidStateStoreException`.
* **Root Cause**: The streams application is starting up or rebalancing, meaning partition ownership is changing and RocksDB stores are locked.
* **Fix**: Catch the exception and retry after a short delay (e.g. 500ms), or wait for the lifecycle to reach the `RUNNING` state.

### 2. Metadata API Returns "Unavailable" Host Details
* **Symptom**: Hostnames return as `unknown` or blank.
* **Root Cause**: The property `application.server.config` was not configured in the streams application properties. Kafka cannot advertise host addresses to other nodes.
* **Fix**: Set `application.server` to `hostname:port` (e.g. `localhost:8080` or container hostname) on each running instance.

### 3. Memory Leak on Iterator Scans
* **Symptom**: Application JVM Out of Memory (OOM) after running range scans.
* **Root Cause**: Calling `store.range()` or `store.all()` returns a `KeyValueIterator`. If you do not close the iterator, native RocksDB memory handles stay open, leaking memory.
* **Fix**: Wrap the iterator call inside a try-with-resources statement: `try (KeyValueIterator<K, V> iterator = store.range(...))`.

## 4. Socratic Review Questions

### Question 1
*How does Kafka Streams resolve which host owns a specific key at runtime?*
* **Answer**: It hashes the key using the active partitioner strategy, maps the hash value to a partition index, and then checks the active cluster assignment mapping to find the hostname associated with that partition.

### Question 2
*Why must we set `application.server` in our properties to use distributed Interactive Queries?*
* **Answer**: Because if it is not set, Kafka Streams cannot share the hostname and port details of the running instance with the other instances in the cluster. Metadata lookups will return empty host values, preventing remote query routing.

### Question 3
*What is the purpose of the `KeyValueIterator.close()` call, and what is the consequence of omitting it?*
* **Answer**: It releases native memory resources allocated by the RocksDB C++ engine during iteration. Omitting it leaks system memory, eventually causing application OOM crashes.

### Question 4
*How can you handle query requests for keys that are not yet materialized in the local state store?*
* **Answer**: Check if `store.get(key)` returns `null`. If it returns `null`, return a `404 Not Found` response to the client, or write a fallback DB query.

### Question 5
*What is the latency trade-off of routing queries to remote instances in a distributed stream setup?*
* **Answer**: Direct queries to a local store take under a millisecond. If the query must be forwarded to a remote instance, it requires a REST network hop, increasing latency to 10-50 milliseconds.

### Lab 13.1 — Local State Store Query API

#### Scenario
We will build a Spring REST Controller that queries a local RocksDB key-value store named `"customer-spend-store"` to perform point lookups.

#### Complete Controller Java Code
Create the file [LocalQueryController.java](file:///c:/Users/Admin/Desktop/projects/learning-repo/courses/src/main/java/com/springkafka/course/controller/LocalQueryController.java) with the following content:

```java
package com.springkafka.course.controller;

import org.apache.kafka.streams.KafkaStreams;
import org.apache.kafka.streams.StoreQueryParameters;
import org.apache.kafka.streams.state.QueryableStoreTypes;
import org.apache.kafka.streams.state.ReadOnlyKeyValueStore;
import org.springframework.kafka.config.StreamsBuilderFactoryBean;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.http.ResponseEntity;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

@RestController
@RequestMapping("/api/spend")
public class LocalQueryController {
    private static final Logger log = LoggerFactory.getLogger(LocalQueryController.class);

    private final StreamsBuilderFactoryBean streamsBuilderFactoryBean;

    public LocalQueryController(StreamsBuilderFactoryBean streamsBuilderFactoryBean) {
        this.streamsBuilderFactoryBean = streamsBuilderFactoryBean;
    }

    @GetMapping("/local/{customerId}")
    public ResponseEntity<Double> getLocalSpend(@PathVariable String customerId) {
        log.info("Querying local state store for Customer ID: {}", customerId);

        // 1. Retrieve the native KafkaStreams instance
        KafkaStreams kafkaStreams = streamsBuilderFactoryBean.getKafkaStreams();
        if (kafkaStreams == null || kafkaStreams.state() != KafkaStreams.State.RUNNING) {
            return ResponseEntity.status(503).body(null); // Service unavailable during rebalance
        }

        try {
            // 2. Fetch read-only store parameters
            ReadOnlyKeyValueStore<String, Double> store = kafkaStreams.store(
                StoreQueryParameters.fromNameAndType(
                    "customer-spend-store",
                    QueryableStoreTypes.keyValueStore()
                )
            );

            // 3. Query the store
            Double totalSpend = store.get(customerId);
            if (totalSpend == null) {
                return ResponseEntity.notFound().build();
            }
            return ResponseEntity.ok(totalSpend);

        } catch (Exception e) {
            log.error("Failed to query local state store", e);
            return ResponseEntity.internalServerError().build();
        }
    }
}
```

### Lab 13.2 — Host Metadata Lookup Service

#### Scenario
We will create a service that checks whether a key is located on the local machine or remote pods by using the `StreamsMetadata` and `KeyQueryMetadata` APIs.

#### Complete Metadata Lookup Java Code
Create the file [MetadataLookupService.java](file:///c:/Users/Admin/Desktop/projects/learning-repo/courses/src/main/java/com/springkafka/course/service/MetadataLookupService.java) with the following content:

```java
package com.springkafka.course.service;

import org.apache.kafka.common.serialization.Serializer;
import org.apache.kafka.common.serialization.Serdes;
import org.apache.kafka.streams.KafkaStreams;
import org.apache.kafka.streams.KeyQueryMetadata;
import org.springframework.kafka.config.StreamsBuilderFactoryBean;
import org.springframework.stereotype.Service;

import java.util.Objects;

@Service
public class MetadataLookupService {

    private final StreamsBuilderFactoryBean factoryBean;
    private final String localHostName = "localhost:8080"; // Configured application.server value

    public MetadataLookupService(StreamsBuilderFactoryBean factoryBean) {
        this.factoryBean = factoryBean;
    }

    public HostInfo resolveHostForKey(String key) {
        KafkaStreams kafkaStreams = factoryBean.getKafkaStreams();
        if (kafkaStreams == null) {
            throw new IllegalStateException("KafkaStreams is offline!");
        }

        Serializer<String> stringSerializer = Serdes.String().serializer();

        // 1. Query metadata for the target key
        KeyQueryMetadata metadata = kafkaStreams.queryMetadataForKey(
            "customer-spend-store",
            key,
            stringSerializer
        );

        if (metadata == null || metadata.equals(KeyQueryMetadata.NOT_AVAILABLE)) {
            throw new IllegalStateException("Metadata mapping not available!");
        }

        // 2. Extract active host details
        org.apache.kafka.streams.state.HostInfo activeHost = metadata.activeHost();
        String host = activeHost.host();
        int port = activeHost.port();

        String hostAddress = host + ":" + port;
        boolean isLocal = Objects.equals(hostAddress, localHostName);

        return new HostInfo(host, port, isLocal);
    }

    // Host details wrapper class
    public static class HostInfo {
        private final String host;
        private final int port;
        private final boolean isLocal;

        public HostInfo(String host, int port, boolean isLocal) {
            this.host = host;
            this.port = port;
            this.isLocal = isLocal;
        }

        public String getHost() { return host; }
        public int getPort() { return port; }
        public boolean isLocal() { return isLocal; }
        public String getAddress() { return host + ":" + port; }
    }
}
```

### Lab 13.3 — REST Query Forwarder

#### Scenario
We will create a controller that resolves key locations. If the key is local, it queries RocksDB; if the key is remote, it forwards the query using Spring `WebClient` to the remote pod.

#### Complete Distributed Controller Java Code
Create the file [DistributedQueryController.java](file:///c:/Users/Admin/Desktop/projects/learning-repo/courses/src/main/java/com/springkafka/course/controller/DistributedQueryController.java) with the following content:

```java
package com.springkafka.course.controller;

import com.springkafka.course.service.MetadataLookupService;
import org.apache.kafka.streams.KafkaStreams;
import org.apache.kafka.streams.StoreQueryParameters;
import org.apache.kafka.streams.state.QueryableStoreTypes;
import org.apache.kafka.streams.state.ReadOnlyKeyValueStore;
import org.springframework.kafka.config.StreamsBuilderFactoryBean;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.reactive.function.client.WebClient;
import org.springframework.http.ResponseEntity;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import reactor.core.publisher.Mono;

@RestController
@RequestMapping("/api/spend")
public class DistributedQueryController {
    private static final Logger log = LoggerFactory.getLogger(DistributedQueryController.class);

    private final StreamsBuilderFactoryBean streamsBuilderFactoryBean;
    private final MetadataLookupService metadataLookupService;
    private final WebClient.Builder webClientBuilder;

    public DistributedQueryController(StreamsBuilderFactoryBean streamsBuilderFactoryBean,
                                      MetadataLookupService metadataLookupService,
                                      WebClient.Builder webClientBuilder) {
        this.streamsBuilderFactoryBean = streamsBuilderFactoryBean;
        this.metadataLookupService = metadataLookupService;
        this.webClientBuilder = webClientBuilder;
    }

    @GetMapping("/query/{customerId}")
    public Mono<ResponseEntity<Double>> querySpend(@PathVariable String customerId) {
        log.info("Query request received for Customer ID: {}", customerId);

        // 1. Resolve host ownership
        MetadataLookupService.HostInfo hostInfo;
        try {
            hostInfo = metadataLookupService.resolveHostForKey(customerId);
        } catch (Exception e) {
            return Mono.just(ResponseEntity.status(503).build());
        }

        // 2. Query locally if key is owned by local partition
        if (hostInfo.isLocal()) {
            log.info("Key belongs to local node. Querying local state store.");
            KafkaStreams kafkaStreams = streamsBuilderFactoryBean.getKafkaStreams();
            ReadOnlyKeyValueStore<String, Double> store = kafkaStreams.store(
                StoreQueryParameters.fromNameAndType("customer-spend-store", QueryableStoreTypes.keyValueStore())
            );
            Double spend = store.get(customerId);
            if (spend == null) {
                return Mono.just(ResponseEntity.notFound().build());
            }
            return Mono.just(ResponseEntity.ok(spend));
        }

        // 3. Forward query to remote host using WebClient
        String forwardUrl = String.format("http://%s/api/spend/local/%s", hostInfo.getAddress(), customerId);
        log.warn("Key lives on remote node. Forwarding query request to: {}", forwardUrl);

        return webClientBuilder.build()
            .get()
            .uri(forwardUrl)
            .retrieve()
            .bodyToMono(Double.class)
            .map(ResponseEntity::ok)
            .onErrorReturn(ResponseEntity.status(500).build());
    }
}
```
